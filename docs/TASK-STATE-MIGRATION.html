The Great Library of SISO · Agents · Architecture decision

One shared task brain, not three competing databases.

This map records what was learned by reading OS Database, Task Manager, PM Tasks, and the published Agent Brain. It is a dated decision with machine-verifiable receipts—not a permanent claim that today’s layout is sacred.

Decision · 2026-07-30
Agent Brain owns shared task state and its API. Project OS owns project structure. Runtime owns session execution. Skills Hub describes callable capabilities. Playbooks own composed procedures. The legacy folders are decomposed along those boundaries rather than promoted wholesale.

The operating flow

Project OSDefines the project, intent, goals, repository rules, and adoption configuration.
Agent BrainStores tasks, atomic step claims, task artifacts, memory, timeline, and coordination state.
Agent RuntimeExecutes sessions and tools, then reports durable facts through the Brain API.
Skills & PlaybooksDescribe atomic capabilities and composed operating procedures; they do not own another database.
First-principles test: data that multiple agents must agree on belongs behind one state contract. Behavior that can change without changing shared state belongs in its own Work and integrates through that contract.

Capability-by-capability result

Observed capabilityCanonical homeDecisionWhy
Task create, read, update, archiveAgent BrainImplementedShared durable truth; writes are allowlisted and authorized.
Role queue and task stepsAgent BrainImplementedThe prior select-then-update race is replaced by one immediate write transaction.
Versioned task artifactsAgent BrainImplementedArtifacts are immutable versions attached to a task and optional step.
Task memory and execution historyAgent BrainReusedExisting memory and typed timeline contracts replace duplicate tables.
Sessions and tool executionAgent RuntimeReclassifiedA session is execution lifecycle, not database ownership.
Projects, missions, goalsProject OSReclassifiedPlanning structure varies by project; Brain retains a project locator on tasks.
Skill/tool catalogSkills HubReclassifiedDiscovery and install metadata version with the capability registry.
Templates and multi-step pipelinesAgent PlaybooksReclassifiedA reusable composition is a playbook, not a state-table feature.
Scheduled automationsFuture Agent Automation WorkDeferredTiming and execution authority need an operator contract independent of storage.
Custom fields and generic relationship graphUnverifiedDeferredNo current consumer evidence justifies importing schema surface.
Arbitrary raw SQLNoneRetiredA public skill adapter must expose stable commands, not database internals.
Machine paths and runtime database filesNoneRetiredConfiguration is explicit; state never ships as source.

What happens to the three legacy units

UnitDispositionMigration rule
os-databaseDecompose, then retirePort only proven behavior to its owning Work. Preserve the reviewed source until migration fixtures prove data portability.
task-managerReplace with Brain adapterKeep familiar commands where useful, but route all reads and writes through siso-brain.
pm-tasksRetire after adapterIt has no independent outcome and currently confuses task IDs with step IDs.

Receipts and reversibility

migrations/003_task_workflow.sql is additive; older migrations remain immutable. npm test creates an isolated database, races two claimants against one step, verifies exactly one claim wins, checks task completion and artifact versioning, replays the offline outbox, merges durable task state, and confirms uninstall preserves data. The machine-readable classification is LEGACY-TASK-STATE-ASSESSMENT.json.

If future evidence shows task workflow deserves a separate service, the stable capability can move behind a new locator. Consumers should depend on the contract, not this repository path.
